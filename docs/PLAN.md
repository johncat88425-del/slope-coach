# 實物模擬實驗教練：找出預測與實測的差異，再設計下一次驗證

版本：第三版，更新於 2026 年 10 月 25 日。用途：Meta 駭客鬆申請、選題與一人十天執行計畫。本版納入朋友建議的影片預測疊加、展示節奏與公平比較，同時修正評分、同步、拒判與因果解讀的限制；其他兩個專案仍保留作比較。

目前狀態是構想與規劃，尚未完成產品、實測、競品完整比較或付費驗證。文中的 85 分是有條件的選題目標，不是官方保證；所有準確率、工時和使用者測試數量都是計畫值。

## 一、這個專案到底要做什麼

使用者拍下桌上的斜坡與滑塊，確認尺寸，先看系統的運動預測，再真的操作並錄影。系統比較預測與實測，指出差異、提出少數可檢查的原因，再建議一個能協助排除原因的小實驗。使用者執行之後，系統更新證據，說明目前比較支持什麼、還不能確定什麼。

核心問題是「為什麼我的實驗和預測不同，下一次該怎樣驗證」。最小完整體驗必須走過觀察、預測、實測、差異、假設、下一次驗證及報告。僅有拍照問答、3D 動畫或一份解說文字，還沒有完成本案。

第一版只支援固定鏡頭、單一斜坡和單一滑塊。選滑塊是為了降低車輪、軸承和轉動慣量帶來的額外未知因素。它不是任意現場轉成精確數位孿生，也不是用照片自動求出所有物理參數。

## 二、為什麼值得選，以及最大的弱點

這個方向能讓評審親眼看見同一個物件的預測與實測，也能展示 AI 面對差異時怎樣繼續工作。即使第一次預測失準，系統仍可以透過有依據的追問和驗證協助使用者，讓失準成為學習過程的一部分。

建議申請主題以 Push the Frontier 為主，強調模型與物理工具一起理解和檢查真實系統；最早的使用情境則選基礎科學教學。影響力必須落在一件具體事情，例如幫帶領者減少整理影片的工作，或讓學生完成一次有意義的變因比較。

最大的弱點是拍攝與校準可能比手動測量麻煩，教育效果也尚未證明。使用者如果只想知道滑了幾秒，普通計時器可能更方便；因此本案必須證明「差異之後的下一次驗證」值得這些額外步驟。

本案也不是全新空白市場。PhET 已有互動力學模擬，Video2World 研究從影片建立可執行模擬。這些直接限制了我們對原創性的主張。[PhET][phet] [Video2World][video2world]

我們需要實際比較的差異，是自己的實驗能否接上可回查的預測、差異分析和下一次驗證。尚未測過相近產品前，只能說這是設計重點，不能說別人都沒有。若相近方案已能同樣完成，而且體驗更好，就要重新選更窄的問題。

## 三、十天內必須完成的範圍

只支援一套裝置、一條直線滑動路徑、一種拍攝方式、兩個驗證情境。第一種是使用者輸入的斜坡高度有誤，第二種是釋放滑塊時帶入了額外初速度。系統不知道測試片被安排了什麼問題，只能根據使用者確認的設定、觀察與工具結果工作。

兩種情境不代表它能診斷所有摩擦、空氣阻力、變形或器材問題。無法區分的原因必須保留為多個假設，或建議重新確認量測。不能因為數學擬合比較好，就宣稱找到了唯一真因。

必做內容是場景與尺寸確認、上傳短片、追蹤校驗、保存預測、比較實測、列出有來源的假設、選擇下一次驗證，以及匯出報告。使用者必須能修改關鍵輸入，也必須看得出哪些資料由自己確認、哪些由影像估計。

本次十天範圍明確排除三維外觀重建、語音控制、即時串流、多種實驗和開放問題診斷。介面使用互動側視圖，優先把事前預測與實測疊在原片上；疊加若未能可靠對齊，就保留同步影片與曲線，不為視覺效果改動數據。

第五天必須跑通整個循環，第七天凍結功能。第八至十天只做測試、修正、部署、錄影和提交，不在最後三天新增另一個模型或實驗類型。

## 四、使用者實際會怎樣操作

使用者先看到一個完整示範，再開始自己的實驗。網站提示固定手機、放好尺、拍到起終點，並確認移動平面大致平行於畫面。使用者輸入斜坡沿面長度和垂直高度，確認滑塊位置。若照片不合拍攝條件，先要求重拍。

接著做三次基準滑動，盡量用相同方式釋放。系統估計這套裝置的有效阻力與重複變異，顯示資料來源與限制。這是校準，不列入後續預測準確率。若滑塊不滑、碰撞、偏航或明顯跳動，基準資料不合用，應重錄或停止分析。

使用者設定下一次要測的坡度。系統在實驗前保存預測曲線、參數和時間。再錄下真正的滑動，得到實測路徑。結果頁同步顯示影片、實測點與先前保存的預測，不能事後悄悄換掉原預測。

若差異超過可解釋的測量範圍，系統提出有限的檢查問題。例如「模型原本假設從靜止釋放，但目前曲線可能存在初速度」；或「加速度差異也可能來自角度或阻力，僅靠本片還無法區分」。每句話要附數據、片段或假設來源。

最後，使用者選擇重新量高度，或在相同角度用一致的釋放方式重做。系統先記錄這次檢查想區分什麼，再接收新結果，比較假設的支持程度。報告保留整個過程，包括沒有解決的問題。

## 五、真正的創意放在哪裡

本案想做出的創意是讓實驗中的意外結果接到下一個可執行的問題。使用者不只是看一個解釋，也能藉由一次小變更檢查解釋是否站得住腳。模型需要根據當下資訊選擇合適的工具和追問，而不是每次輸出相同答案。

這個創意成立的條件是建議能被測試，並且能改變後續判斷。如果系統無論看到什麼都只叫人重錄，或總是說摩擦力不同，就沒有完成承諾。相同資料與設定應產生一致的基本數值，敘述不能蓋過測量結果。

這仍屬於待查證的產品差異，不等於全球原創。競品比較應看同一套任務是否已被支援，不能只看別人的首頁有沒有使用相同名稱。

## 六、模型分工與必要性

Muse Spark 負責理解場景、使用者問題和可見事件，整理成受限制的設定。SAM 3.1 負責物件輪廓和位置追蹤。小物件、模糊和遮擋的效果需要自行測試，官方能力描述不是本專案的準確率保證。[Spark][spark] [SAM][sam]

Wonder 可以接收已驗證的測量結果，選擇模擬、比較或下一次驗證工具，並解釋理由。初期若 Spark 已能完成同樣工作，就保留較簡單、成本較低的方案；是否增加 Wonder 取決於實測，不以模型數量當成技術深度。[Wonder][wonder]

長度換算、曲線擬合、公式、誤差和參數檢查由程式完成。模型不能任意改動測試答案，也不能直接執行自由生成的分析程式。固定工具回傳數字、適用條件和錯誤狀態，模型只據此組織下一步。

Muse Code 可協助開發。Muse Image 不參與證據產生；Voice Transcribe 不列入必做；Glimmer 本機部署也不納入十天範圍。公開說明只列出實際使用、測試過的工具。

## 七、物理計算與不能亂說的地方

採用沿斜坡的一維位置 s，以秒為時間、米為距離。對已開始滑動且近似定加速度的區段，使用 s(t) = s0 + v0t + 0.5at²。簡化滑動模型的加速度為 a = g(sinθ − μcosθ)，斜坡角度由確認的高度 h 和沿面長度 L 得到 θ = arcsin(h/L)。必須檢查 0 < h < L 及單位合法。[基本力學][forces] [摩擦與斜坡][friction]

μ 是根據裝置與條件估計的有效動摩擦參數，不是靠照片辨認出的材料常數。靜摩擦決定是否開始滑動，不能直接拿動摩擦模型判斷是否會起滑。第一版只分析已確實滑動的試驗；未開始滑動就要求改變條件並重新確認。

一條軌跡即使可以擬合 a 和 v0，也不能唯一判定角度、阻力和釋放問題。例如角度偏差與阻力變化都可能改變加速度。系統可以說結果與某個假設一致，但需要額外量測或重做才能進一步判斷。不得用「已查出真因」取代仍不確定的證據。

基準資料估出的參數，要先鎖定再測新影片。後續若重新校準，建立新版本，同時保留原始預測和誤差。不能用同一段測試影片更新參數，再報告該片預測很準。

誤差範圍要來自重複試驗、人工標記差異及計算假設。第一版不硬給看似精確的 95% 信賴區間，也不把語言模型的自信程度當成物理不確定性。

## 八、只支援兩種下一次驗證

第一種是尺寸核對。當加速度明顯與模型不符，且畫面不足以判斷角度或阻力時，請使用者用尺重測高度與沿面長度。其餘條件先保持一致，輸入修正值後先保存新預測，再錄下一次試驗。若差異縮小，可說修正設定有助解釋結果，仍不代表排除了全部因素。

第二種是釋放方式核對。當擬合顯示可能有非零初速度，請使用者在原角度、原表面和原起點，改用簡單擋片釋放，盡量避免向前推。再次拍攝釋放區段。若開頭被遮住，只能比較後續運動，不能宣稱知道手是否推了。

兩種驗證的建議、需保持的條件和預期觀察，先寫成小型受限制資料庫。模型只能選擇或要求澄清，不能自行發明新的器材操作。若結果仍不支持其中任何一個解釋，輸出「目前證據不足」並保留紀錄。

這套設計能讓十天內的研究重點放在選擇和核對，而不是建立通用科學推理平台。是否真的幫助使用者，需要在第八天測試。

## 九、拍攝與追蹤要求

手機固定在支架上，光線穩定，滑塊顏色和背景有對比，畫面包含尺及整段路徑。參照尺應盡量位於同一運動平面。先使用近似正側視，畫面存在明顯透視或鏡頭移動就要求重拍；不承諾自動恢復任意鏡頭幾何。

先由使用者點選校準線段和滑塊，再自動追蹤。保存每個實際影格的時間戳。偵測到目標消失、面積異常或位置跳動時，標記不可用區段，不把缺失點當成真實觀測。需要插值時必須標為估計，且不能拿插值掩蓋關鍵事件。

自動追蹤不穩時，允許手動確認少量位置作救援。這仍能完成預測與驗證循環，但 demo 與報告必須顯示人工介入。若連人工參照都無法可靠量測，停止產生數值診斷。

## 十、軟體如何實作

前端只有五個主要區域：場景設定、預測、影片分析、下一次驗證、實驗報告。它們對應同一個實驗紀錄，使用者隨時可以回到前一步查看資料。第一版使用一般網頁、二維圖表與可靠時才顯示的影片位置疊加，不開發 3D。

後端負責媒體上傳、工作狀態、模型呼叫、輸出檢查和報告。數值服務負責校準、追蹤資料轉換、曲線擬合及比較，工具介面固定為建立設定、估計基準、保存預測、分析試驗、比較結果、提出驗證及匯出報告。

資料以 experiment_id 串起 calibration_version、trial_id、prediction_id 和 intervention_id。每個 trial 保存原片、實際時間戳、位置、人工修正與品質標記；每個 prediction 保存建立時間、使用的參數與假設。模型提案、使用者選擇和最後結果分開保存。

API 金鑰放後端。模型回傳格式、數值範圍和引用來源都要檢查，無法通過就回到待確認狀態。所有工作有超時和重試上限，重新整理頁面不會重複建立同一次收費任務。

## 十一、要完成哪些東西才算交付

首先，別人能打開網站，使用內建示範或依拍攝指引完成一套受支援實驗。若上傳不合條件，介面要明確說明原因，不能無限停在分析中。

其次，預測必須在接收測試影片前保存；分析後可看到實測與預測的比較，並能打開原始影片。尺寸或參數有改變時，要能看見版本差異。

第三，至少完成一種能端到端運作的下一次驗證，第二種作為爭取高分的優先增強。若時間不足只保留一種，要重寫對外範圍；不能展示兩個按鈕卻只有一個可用。

第四，至少具備三個可重跑案例：接近預測、出現可進一步核對的偏差，以及資料不足而停止判斷。每個案例保存輸入、輸出、模型版本和人工介入。

## 十四、測試資料與驗收數字

目標準備約二十四段短片，每段約五至十五秒，分配為八段開發、六段基準與重複校準、十段最後保留測試。保留測試包含正常、兩種偏差情境及拍攝不合格案例，逐案公布結果，不只報一個總分。

資料由自己安排條件並記錄真實設定。模型不會收到預設原因標籤。人工標記起終時間及選定影格位置，記錄量測方法；若只有一人標記，要承認參照也有不確定性，不稱為絕對真值。

測量指標包括位置誤差、到達時間誤差、可用追蹤比例、錯誤拒判、沒有來源的結論，以及人工修正次數。內部初始門檻可設為合格且獨立的正常試驗，到達時間相對誤差中位數不高於 15%，可見運動區段至少 80% 可量測。這是開發門檻，不是已達到結果或學術標準；必須同時報告樣本數和失敗。

診斷部分要檢查系統是否提出與資料相容的有限假設、是否選到可區分原因的核對方式，以及資料不足時是否保留未知。不能把猜中安排的標籤當成真正證明因果；也不能以誤報少掩蓋完全不提供有用建議。

至少比較三種情況：人工計時與檢查、只把影片交給 Muse 問答，以及完整追蹤加工具驗證的版本。使用相同素材，計入設定和人工修正時間。若完整系統沒有提供可重現的額外價值，要縮小主張。

## 十五、85 分到底指什麼

舊版的 72 分是自訂選題決策分；按照官方四項權重，舊構想的規劃估分是 77 分。兩者都沒有實作證據，不是官方評分。這次新增「下一次驗證」是能力目標，不能因此直接宣布已經 85 分。

如果談官方面向的高分目標，可設定影響力 8.5／10、Meta 工具運用 9／10、技術深度 8.5／10、Demo 9／10，按 30%、25%、20%、25% 換算為 87.5／100。這只是展示需要達到的品質，不是預測評審會給的分數。

若仍用先前自訂決策公式，官方面向占 40%、十天完成性占 30%、差異占 15%、付費理由占 15%，還需要完成性 9／10、差異 8／10、付費理由 7.5／10，才會得到 85.25／100。分數的小數只用於說明計算，不具有統計精度。

這些高分必須靠實際證據重新評估。若技術和展示提高，但付費理由仍停在原本 5／10，其他採相同目標值，決策分只到 81.5／100。因此，85 分不會由堆功能自動得到，也不能在沒有買家資訊時替商業分數加分。

## 十六、影響力要怎樣接近高分

先只服務一群人，例如帶領基礎斜坡活動的教師或科學工作坊主持人。主要任務是讓參與者完成一次「發現差異、選擇核對、解讀新結果」，避免把大學研究、機械工程和家庭教育都混在同一個承諾。

技術上最重要的是單位、時間、校準、預測版本及因果判斷邊界。每個結論都有資料來源，數據可重新計算，系統知道哪些情況不能分析。高分技術深度不需要從零訓練模型，但需要對現成模型的失敗有完整處理。

第九天用乾淨狀態做三次完整彩排，至少包含一次新拍素材。保存失敗次數、實際耗時和人工介入；這是可靠度證據的起點，不是三次成功就能證明普遍可靠。預錄、快取和現場呼叫要標示清楚，不能用不同任務的畫面拼出一次自主成功。

## 十九、你最需要注意的事情

最容易犯的錯，是把漂亮動畫當成精確模擬。影片疊加、曲線和文字都要來自同一套確認參數，時間與空間對齊也必須能回查。外觀與測量沒有支持的細節，不要假裝已經恢復。

第二個錯，是為了讓預測看起來準，用同一段測試影片反覆調參。校準、開發和保留測試要分開，舊結果不能被新參數覆寫。

第三個錯，是把相關性說成因果。估到非零初速度，不等於證明使用者用手推；加速度不同，也不等於證明摩擦力變了。模型只能說資料和假設是否一致，並協助取得新的證據。

第四個錯，是追求功能完整而失去十天交付。先把一套循環做到可用，所有額外功能都要接受刪除。第五天沒跑通就砍功能，第七天凍結，第十天交付真實能做的範圍。

第五個錯，是把官方模型宣傳、內部門檻或少量試用寫成產品成果。申請和發表只能區分已完成、計畫中與尚未證明的事情；有競品也不代表不能做，但差異必須實際比較。

## 二十四、影片上的預測位置疊加怎麼做

使用帶文字標籤的青色虛線框表示事前預測，橘色實線框表示實測，避免只用紅綠色區分。預測框是沿確認路徑移動的示意框，不聲稱每個像素都是實物的精確輪廓；實測輪廓則來自追蹤或有標示的人工位置。

空間映射沿同一運動平面上的已確認路徑建立，以起點像素和每米對應像素，把 s(t) 轉回畫面。尺規、路徑和鏡頭條件未通過檢查就不顯示疊加。比例換算只在這個近似側視條件下成立，不擴張為任意透視影像的幾何重建。

時間軸特別容易造成錯判。保存每幀媒體時間，以及使用者確認或可見事件辨識的釋放時刻 t0，播放時以媒體時間減 t0 查詢已保存的預測；不能靠找最佳吻合而事後平移預測。預測接觸終點就停止，不能穿過坡底繼續畫。

擬合初速度還需要可信的時間原點與起始位置。若釋放時刻不清楚，時間偏移本身就可能表現成非零初速度；所以只有開頭資料、時間原點和校準充分時，才把它列為可檢查假設。不要單靠一個擬合數字說「顯著非零」，需先評估標記誤差和擬合穩定性。

同一套確認參數不代表重做後兩框必然重疊。展示實際的誤差變化；若沒有收斂，保留結果並說明假設未獲支持。遮擋時隱藏實測框或標示缺失，不能把內插框裝成 SAM 觀測。若校準和時間原點已完成，繪圖可能是小工作；完整同步與驗證不承諾只要一點五至兩小時。兩小時是停止投入的預算，不是完成保證。

## 二十五、展示腳本與拒判要怎樣修正

建議三分鐘，仍以正式提交要求為準。零至二十五秒呈現一段確實存在差異的預測與實測疊加，說明「實驗與預測不同，怎樣選下一個檢查？」不要說一般 AI 必然瞎猜，除非本次公平測試確有此結果。

二十五至七十秒顯示事前保存的預測、可回查的起滑時間和測量，呈現模型如何提出釋放方式假設與擋片核對。介面讓人看懂資料先後關係即可，不必把所有內部識別碼放滿畫面。

七十至一百一十五秒展示擋片操作、新片分析和實際誤差變化。在收取新片之前保存這一輪預測與待驗假設；是否支持假設依結果決定，不預寫成功結論。剪輯可縮短等待，標示預錄、加速、快取及人工介入。

一百一十五至一百五十秒展示遮擋或不可靠的起滑資料，以及系統為何不提供某個結論。拒判不能僅依「可追蹤比例低於 80%」。即使比例很高，只要起滑關鍵區段缺失，也可能無法判斷初速度；反之，部分非關鍵區段缺失不一定妨礙某項量測。分別檢查校準、時間原點、有效觀測數、關鍵區段、位置跳動與擬合適用性，明確指出還能說什麼。

最後三十秒呈現保留測試、比較結果和目標使用者的實際任務表現，只放已測出的數字。保留一個失敗或限制，讓觀眾知道能力邊界。不要承諾完成腳本便會拿到 92 分。

## 二十六、公平對照與最終完成門檻

朋友提供的對照表不能直接當結果。人工可以用試算表先算曲線，Muse 也可能拒絕判斷，因此不能預先把人工限制成只有單點計時，或把 Muse 寫成一定亂猜。比較前固定任務、可見設定、校準資料、時間預算和計分規則；各組拿到完成任務所需的相同資訊，外加工具和人工時間如實記錄。

人工組允許其通常會用的計時或試算方式，記錄使用方法。Muse 組使用確認的設定與相同影片，固定提示且不提供答案標籤；若只測一次直接問答，名稱寫成「本次單輪問答基準」，不能代表所有 VLM 或最佳代理。完整系統則列出追蹤、數值工具和模型選擇的額外成本。若要進一步區分到底是哪個元件有幫助，再做少量移除元件的消融；三種流程比較本身不等於已完成嚴格消融。

十段保留測試中有不合格影片，各項指標的適用分母不同。位置或時間誤差只報可量測案例的 n，同時列出全部十段的成功、拒判、誤判與失敗；不能把拒判案例從總體結果消失。重拍驗證的成對影片另行列出，不把同一段重跑多次當成新增獨立樣本。

結果表至少呈現每組的可分析數／總數、到達時間誤差、與證據一致的假設與核對建議數、正確及錯誤拒判、人工修正次數、完整任務耗時與 API 成本。尚未測量一律標「尚未測量」，不預填優勝結論。若同一人重複做三組任務，要記錄順序和熟悉效應；小樣本只做描述，不宣稱統計上優於所有替代方案。

新增疊加與呈現仍在原本六十小時內，優先取代美術與第二種驗證的時間，不增加總預算。第三天有可信比較曲線，第五天跑通一種驗證，第七天凍結，第八天測使用者，第九天三次彩排，第十天提交，這些都是管理門檻而非保證。只有真實完成、失敗處理、獨立比較和使用者價值都有證據後，才重新評估是否值得給 85 分以上；單靠這份強化指南沒有可驗證的 92 分依據。
